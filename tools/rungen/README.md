# tools/rungen: эталонный генератор забега

Чистая логика без движка: на вход зерно, на выход раскладка забега. Отсюда она
переносится в Unreal, а `golden/*.json` проверяют, что порт считает то же самое.
Источник истины по механикам: DESIGN.md, разделы 5.4–5.8, и допущения в разделе 14.

Только Python 3 из стандартной библиотеки, ничего ставить не нужно.

```
cd tools/rungen
python3 -m unittest -v test_rungen     # тесты, ~1 мин
python3 sim.py --seeds 5000            # прогон всех игроков на текущих числах
python3 sim.py --seeds 5000 --start-5-8  # то же на стартовых числах из 5.8
python3 balance.py                     # перебор сетки чисел, пишет BALANCE.md (~5 мин)
python3 dump.py --seed 42              # раскладка одного зерна в JSON
python3 dump.py --golden               # переписать эталоны после смены правил или чисел
```

| Файл | Что внутри |
|---|---|
| `rng.py` | Детерминированный ГСЧ на 32-битной арифметике. Правила в шапке файла |
| `config.py` | Числа баланса. `DEFAULT` подобран, `START_5_8` — стартовая точка из 5.8 |
| `content.py` | 16 предметов с брифами для моделей и шаблоны записок на английском |
| `generator.py` | Генератор и статическая проверка раскладки `validate_layout` |
| `sim.py` | Мир из копий комнат и модели игроков |
| `balance.py` | Перебор чисел по сетке, отчёт `BALANCE.md` |
| `dump.py`, `golden/` | Дамп раскладки и эталоны для порта |
| `test_rungen.py` | Тесты |

## Алгоритм (спецификация для порта)

Всё случайное берётся из `Rng(seed, домен, ...)`. У каждой величины свой ключ,
поэтому она не зависит от того, что и в каком порядке считалось до неё.
Порядок вызовов внутри одного `Rng` важен и помечен в коде комментариями `rng:`.

### 1. Роли предметов

Каталог из 16 предметов перемешивается `Rng(seed, D_ROLES)`. Первые `items_in_run`
идут в забег. Из них первые шесть получают роли по порядку: L (проводник), K1, K2, K3
(финальный набор), X, Y (ложные). Остальные — пустышки. Блокнот, оружие и скафандр
вне каталога.

### 2. Сигнатура и ключ комнаты

Сигнатура — маска ролей значимых предметов в кармане, 6 бит: L=1, K1=2, K2=4, K3=8, X=16, Y=32.
Пустышки и повторы не учитываются. Ключ комнаты = маска, а если маска пустая — 64,
когда в кармане есть блокнот, и 0, когда нет. Ключей всего 128, счётчик копий — массив `int[128]`.

### 3. Классы комнат и уровни цепочки

| Ключ | Класс | Уровень | Тип отсека |
|---|---|---|---|
| 0 (карман пуст) | рубка | — | рубка |
| 64 (только блокнот) | цепочка | 0, жилая петля | жилая |
| {L} | цепочка | 1 | `level_type[1]` |
| {L,K1}, {K1} | цепочка | 2 | `level_type[2]` |
| {L,K1,K2}, {K1,K2} | цепочка | 3 | `level_type[3]` |
| {K1,K2,K3} | двигатель | 4 | двигательный |
| всё остальное | догадка | — | `hash32(seed, D_GUESS_TYPE, key) % 3` из жилой, лаборатории, жизнеобеспечения |

`level_type[1..3]` выбираются `Rng(seed, D_LEVEL_TYPE)` так, что соседние уровни
различаются по типу: выход из петли видно сразу.

### 4. Вид комнаты: тип + переключатели

Для каждого обычного типа (жилая, лаборатория, жизнеобеспечение) перестановка
`switch_of[type][role]` из `Rng(seed, D_SWITCH, type)`: каждый значимый предмет включает
ровно один из шести переключателей. Переключатели комнаты — OR по ролям в ключе.
У жилой петли переключателей нет. У рубки и двигательного отсека они косметические,
постоянные на забег: `hash32(seed, D_COSMETIC, type) & 63`. Одна сигнатура в одном
забеге всегда даёт один вид, разные сигнатуры — разные виды (проверяется).

### 5. Копия комнаты (`room_copy(key, copy)`, copy с 1)

Счётчик копий растёт при каждом раскрытии двери с этим ключом. Содержимое копии:

1. **Аномалия** `Rng(seed, D_ANOMALY, key, copy)`: шанс `p_meaningful` на цепочке,
   `p_guess` в догадке, 0 в рубке и двигательном. Тип аномалии равновероятно из четырёх ядровых.
2. **Двери** `Rng(seed, D_DOORS, key, copy)`: от `doors_min` до `doors_max` нераскрытых плюс входная.
3. **Предметы** `Rng(seed, D_ITEMS, key, copy)`:
   - только на цепочке: нужный следующий предмет (L, K1, K2 или K3 по уровню) лежит,
     если выпал шанс `p_target` (бросок делается всегда) или это копия номер
     `1 + hash32(seed, D_GUARANTEE, key) % target_guarantee_by`;
   - прочие: от `filler_min` до `filler_max` штук без повторов из пустышек и X, Y по весам.
   Предметы цепочки лежат только как «нужный следующий», поэтому правило 5.7.2
   («K2 только там, где сигнатура содержит K1») выполняется строже, чем «может лежать».
4. **Записки** `Rng(seed, D_NOTES, key, copy)`:
   - в первой копии каждой комнаты цепочки — записка на шаг вперёд: уровень 0 говорит про K1,
     1 — про K2, 2 — про K3, 3 — финальный набор. Так каждое звено можно узнать раньше,
     чем оно понадобится (5.7.4);
   - с шансом `p_extra_note` ещё одна: «выход из петли», повтор записки на шаг вперёд,
     «бесполезен», «опасен» (веса 2:2:2:1); в первой копии повтор заменяется на «выход из петли»;
   - в догадке с шансом `p_guess_note` одна записка «бесполезен» или «опасен» (2:1);
   - в двигательном отсеке — записка о возвращении в рубку.

Стартовая рубка: блокнот, две пустышки, три двери, без аномалии. Первая запись блокнота
называет L. Двигательный отсек и рубка безопасны.

### 6. Записки

Шаблоны в `content.py`, подстановки `{item}`, `{Item}`, `{item2}`, `{item3}`, `{prereq}`,
`{leader}`, `{Leader}` (в Unreal это `FText::FormatNamed`). Каждая записка правдива,
это проверяет `note_is_true` по ролям независимо от того, как записка создана.

## Модели игроков (только для симуляции)

- **По запискам** — берёт предмет, только если записка назвала его нужным и всё, что для него
  нужно, уже в кармане. Ничего другого не берёт. Когда карман полон, выбрасывает самый ранний
  ненужный (на последнем шаге это L). За замеченным раньше нужным предметом возвращается,
  если по пути нет аномальных комнат. Иначе раскрывает новые двери.
- **Наугад** — записки не читает. Блокнот держит, каждый увиденный предмет с шансом 1/2 берёт
  (при полном кармане с шансом 1/2 меняет на случайный), в 80% случаев раскрывает новую дверь,
  иначе идёт в случайную раскрытую.
- **Умный перебор (дополнительно)** — записки не читает, но знает, что значимый предмет меняет
  вид комнаты. Проверяет незнакомые предметы по одному, оставляет те, что изменили вид без урона.
  Это не просили, но он отвечает на вопрос из 5.6: не выгоднее ли перебор чтения.
- Урон: аномальная комната ранит при первом входе с шансом `hit_first` (1.0, то есть шанс
  аномалии и есть шанс урона), при повторном — `hit_revisit` (0.5). Одно попадание за вход.
  Смерть, когда попаданий набралось `health`.
- Победа: вход в двигательный отсек, затем карман опустошается (блокнот последним)
  и дверь ведёт в рубку. Последняя дверь входит в счёт дверей.

## Перенос в Unreal

- `rng.py` → `FRunRng` (uint32, функции `Mix32`, `Hash32`). Вероятности сравнивать
  через 16-битный порог, как в `chance`, а не через float.
- `RunLayout` → `FRunLayout` (USTRUCT): `RunItems`, `RoleItem[6]`, `ItemRole[16]`,
  `LevelType[4]`, `SwitchOf[3][6]`, косметика рубки и двигателя. Строится один раз на забег.
- `look`, `room_copy`, `start_room` → функции без состояния от `(Layout, Key, Copy)`.
- Состояние забега: `CopyCount[128]` и дерево комнат (у комнаты ключ, номер копии, двери
  с id целевой комнаты или −1, лежащие предметы, флаг «посещена»). Содержимое копии
  генерируется при раскрытии двери и дальше живёт в состоянии: подобранное исчезает,
  выброшенное остаётся (5.3).
- Проверка порта: для зёрен из `golden/` вывести то же, что `dump.py`, и сравнить.

## Результаты

`python3 sim.py --seeds 5000`, зёрна 1–5000. Сетка и проверка на свежих зёрнах — в `BALANCE.md`.

Ошибок генератора нет: статическая проверка 0 из 5000, непроходимых по запискам 0 из 5000
(игрок по запискам с бесконечным здоровьем доходит до конца в каждом забеге).

| | Стартовые числа 5.8 | Подобранные (`DEFAULT`) |
|---|---|---|
| Числа | 4 HP, аномалия 15% / 85%, предмет 35%, гарантия к 3-й копии | 4 HP, аномалия 18% / 85%, предмет 20%, гарантия к 5-й копии |
| По запискам: победа | 98.8% | 91.5% |
| По запискам: дверей до победы, медиана (10–90%) | 8 (6–10) | 11 (8–14) |
| По запискам: урон в среднем | 0.96 из 4 | 1.64 из 4 |
| По запискам: побед с уроном | 63% | 80% |
| По запискам, пропуская 30% записок: победа | 97.2% | 89.1% |
| Наугад: смерть / победа | 99.8% / 0.2% | 99.9% / 0.06% (3 из 5000) |
| Наугад: урон | 3.99 из 4 | 4.00 из 4 |
| Умный перебор (доп.): победа | 27.9% | 12.6% |

Чтение записок выгоднее перебора: 91% побед против 13% у умного перебора и почти нуля
у случайного. Умный перебор при этом выигрывает примерно в каждом восьмом забеге.
Если это много, следующий рычаг — вес ложных предметов: при весе 3 его победы падают
примерно до 9%, а игроку по запискам это ничего не стоит (таблица в конце `BALANCE.md`).
Поднимать шанс аномалии в догадке бесполезно: умный перебор тогда точнее отличает ложные
предметы по урону и выигрывает чуть чаще.

### Чего симуляция не знает

- Урон — абстракция: «аномалия = попадание» при первом входе и 50% при повторном.
  Насколько аномалии бьют на самом деле, покажет только игра.
- Игрок по запискам здесь идеальный: всегда понимает записку и видит все предметы в комнате.
  Живой игрок будет ошибаться, поэтому 91% — верхняя оценка.
- Время в комнате не моделируется. 11 дверей — это длина забега в дверях, а не в минутах.
- Скафандра, лечения, оружия и противников нет.

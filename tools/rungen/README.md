# tools/rungen: эталонный генератор забега

Чистая логика без движка: на вход зерно, на выход раскладка забега. Отсюда она
переносится в Unreal, а `golden/*.json` проверяют, что порт считает то же самое.
Источник истины по механикам: DESIGN.md, разделы 5.4–5.8, и допущения в разделе 14.

Только Python 3 из стандартной библиотеки, ничего ставить не нужно.

```
cd tools/rungen
python3 -m unittest -v test_rungen     # тесты, ~1 мин
python3 sim.py --seeds 5000            # прогон всех игроков на текущих числах
python3 balance.py                     # перебор сетки чисел, пишет BALANCE.md (~9 мин)
python3 dump.py --seed 42              # раскладка одного зерна в JSON
python3 dump.py --golden               # переписать эталоны после смены правил или чисел
```

| Файл | Что внутри |
|---|---|
| `rng.py` | Детерминированный ГСЧ на 32-битной арифметике. Правила в шапке файла |
| `config.py` | Числа баланса. `DEFAULT` подобран, `START_5_8` — стартовая точка из 5.8 |
| `content.py` | 16 предметов с брифами для моделей и шаблоны записок на английском |
| `generator.py` | Генератор и статическая проверка раскладки `validate_layout` |
| `sim.py` | Мир из комнат и дверей и модели игроков |
| `balance.py` | Перебор чисел по сетке, отчёт `BALANCE.md` |
| `dump.py`, `golden/` | Дамп раскладки и эталоны для порта |
| `test_rungen.py` | Тесты |

## Алгоритм (спецификация для порта)

Всё случайное берётся из `Rng(seed, домен, ...)`. У каждой величины свой ключ,
поэтому она не зависит от того, что и в каком порядке считалось до неё.
Порядок вызовов внутри одного `Rng` важен и помечен в коде комментариями `rng:`.

### 1. Роли предметов

Каталог из 16 предметов перемешивается `Rng(seed, D_ROLES)`. Первые `items_in_run`
идут в забег. Из них первые `4 + extras` — значимые, роли по порядку: L (проводник), K1, K2, K3
(финальный набор), затем лишние значимые E1, E2, ... Остальные — пустышки. Блокнот, оружие
и скафандр вне каталога.

Опасных предметов нет (решение автора 13.11): опасны сочетания. Лишний значимый предмет сам
не вредит, но любой набор с ним лежит вне правильного пути.

### 2. Сигнатура и ключ комнаты

Сигнатура — маска ролей значимых предметов в кармане: L=1, K1=2, K2=4, K3=8, E1=16, E2=32 и так далее,
не больше 12 битов. Пустышки и повторы не учитываются. Ключ комнаты = маска, а если маска пустая —
4096 (`ANCHOR`), когда в кармане есть блокнот, и 0, когда нет.

### 3. Классы комнат и уровни цепочки

| Ключ | Класс | Уровень | Тип отсека |
|---|---|---|---|
| 4096 (только блокнот) | цепочка | 0, первая петля | рубка |
| 0 (карман пуст) | цепочка | 0 | жилая |
| {L} | цепочка | 1 | по хешу |
| {L,K1}, {K1} | цепочка | 2 | по хешу |
| {L,K1,K2}, {K1,K2} | цепочка | 3 | по хешу |
| {K1,K2,K3} | двигатель | 4 | двигательный |
| всё остальное, включая любой набор с лишним значимым предметом | догадка | — | по хешу |

«По хешу» — `ORDINARY_TYPES[hash32(seed, D_ROOM_TYPE, key) % 3]`: жилая, лаборатория или
жизнеобеспечение. Тип отсека не обязан меняться на шаге цепочки. Выход из петли видно по
переключателям и поведению комнаты: комната может выглядеть так же, но с аномалией
(решение автора 13.11). Стартовая рубка — комната ключа 4096, в которой ещё лежит блокнот.

### 4. Вид комнаты: тип + переключатели

Переключателей в отсеке шесть. Для каждого обычного типа (жилая, лаборатория, жизнеобеспечение)
`switch_of[type][role]` из `Rng(seed, D_SWITCH, type)`: сначала перестановка шести номеров — её получают
первые шесть ролей, по одному переключателю на каждую; затем для каждой следующей роли `below(6)`.
Переключатели комнаты — OR по ролям в ключе.
У жилой при пустом кармане переключателей нет. У рубки и двигательного отсека они
косметические, постоянные на забег: `hash32(seed, D_COSMETIC, type) & 63`.

Одна сигнатура в одном забеге всегда даёт один вид. Наборы правильного пути выглядят по-разному
(проверяется). Прочие наборы могут совпасть видом: комната выглядит так же, но она другая.

### 5. Комната набора (`room(key)`)

Решение автора 13.11: неважно, какую дверь раскрыть, важно, что в руках. Всё в комнате зависит только
от зерна и ключа. Сколько бы дверей ни раскрыли с одним набором, за ними та же комната с теми же вещами;
взятое не появляется снова, выброшенное остаётся. Номера копии больше нет.

1. **Аномалия** `anomaly_of(key)`, `Rng(seed, D_ANOMALY, key)`. У комнат цепочки и двигательного отсека
   аномалий нет: правильный путь безопасен. У догадки аномалия есть с шансом `p_guess` (сейчас 1,0: всегда),
   вид — равновероятно из четырёх ядровых.
2. **Двери**: четыре — север, юг, запад, восток. У комнаты за каждой дверью двери свои: обратный путь
   ведёт туда, откуда пришёл.
3. **Предметы** `Rng(seed, D_ITEMS, key)`:
   - предмет правильного пути `target_of(key)` лежит всегда: в рубке (только блокнот) — L, в {L} — K1,
     в {L,K1} и {K1} — K2, в {L,K1,K2} и {K1,K2} — K3. В жилой комнате пустого кармана его нет;
   - прочие: от `filler_min` до `filler_max` штук без повторов из пустышек и лишних значимых
     по весам `dummy_weight` и `extra_weight`.
4. **Записки** `Rng(seed, D_NOTES, key)`:
   - в каждой комнате цепочки — записка на шаг вперёд: уровень 0 говорит про K1, 1 — про K2,
     2 — про K3, 3 — финальный набор (5.7.4);
   - с шансом `p_extra_note` вторая: «выход из петли», «бесполезен» или «опасная пара» (веса 2:2:1);
   - в догадке с шансом `p_guess_note` одна записка «бесполезен» или «опасная пара» (2:1);
   - «опасная пара» называет два значимых предмета, набор ровно из которых даёт комнату с аномалией:
     случайная из списка `danger_pairs` (пары по номерам ролей). Если таких пар нет — «бесполезен»;
   - в двигательном отсеке — одна записка «вспомни, как ты попал в рубку» (`N_FINALE`),
     предметов и аномалии нет.

Стартовая рубка `start_room()` — это комната набора «только блокнот», в которой ещё лежит сам блокнот.
Первая запись блокнота называет L, и L лежит тут же. Взяв один блокнот и раскрыв дверь, игрок
попадает в ту же рубку: первая петля.

### 6. Записки

Шаблоны в `content.py`, подстановки `{item}`, `{Item}`, `{item2}`, `{item3}`, `{prereq}`,
`{leader}`, `{Leader}` (в Unreal это `FText::FormatNamed`). Каждая записка правдива,
это проверяет `note_is_true` по ролям независимо от того, как записка создана.

## Модели игроков (только для симуляции)

- **По запискам** — берёт предмет, только если записка назвала его нужным и всё, что для него
  нужно, уже в кармане. Ничего другого не берёт. Когда карман полон, выбрасывает самый ранний
  ненужный (на последнем шаге это L). За замеченным раньше нужным предметом возвращается,
  если по пути нет аномальных комнат. Иначе раскрывает новые двери.
- **Наугад** — записки не читает. Блокнот держит, каждый увиденный предмет с шансом 1/2 берёт
  (при полном кармане с шансом 1/2 меняет на случайный), в 80% случаев раскрывает новую дверь,
  иначе идёт в случайную раскрытую.
- **Умный перебор (дополнительно)** — записки не читает, но знает, что значимый предмет меняет
  вид комнаты. Проверяет незнакомые предметы по одному, оставляет те, что изменили вид без урона.
  Про то, что опасны сочетания, а не предметы, он не знает и ранивший предмет считает плохим.
  Это не просили, но он отвечает на вопрос из 5.6: не выгоднее ли перебор чтения.
- Урон: у комнаты за каждой дверью свой флаг «аномалия действует». При входе в комнату с действующей
  аномалией — попадание с шансом `p_hit` (1.0), затем аномалия устраняется с шансом `p_fix` (0.5).
  Устранённая в этой комнате больше не бьёт, состояние пройденных комнат сохраняется. Комната
  за новой дверью начинает с исходного состояния (решение автора 13.11). Смерть, когда
  попаданий набралось `health`. `p_hit` и `p_fix` — модель игрока, в игру не переносятся.
- Победа: вход в любую рубку после того, как игрок побывал в двигательном отсеке. Концовка
  наступает раньше, чем действует аномалия. Модель игрока в двигательном отсеке выкладывает всё,
  кроме блокнота, и раскрывает дверь: один блокнот — ключ 4096, рубка. Последняя дверь входит
  в счёт дверей.

## Перенос в Unreal

Сделан 13.11: `Source/MegaJam/Run/RunGen.h` и `RunGen.cpp`. После правки `content.py` или `config.py`:

```
python3 tools/rungen/dump.py --golden      # обновить эталоны
python3 tools/rungen/export_cpp.py         # выгрузить каталог, тексты и числа в C++
<пересобрать проект>
python3 tools/ue/check_port.py             # сверить Unreal с эталонами
```

Как устроено соответствие:


- `rng.py` → `RunGen::FRng` (uint32, функции `Mix32`, `Hash32`). Вероятности сравниваются
  через 16-битный порог, как в `chance`, а не через float.
- `RunLayout` → `FRunLayout`: роли предметов, переключатели, опасные пары. Строится один раз на забег.
- `look`, `anomaly_of`, `room`, `start_room` → методы без состояния от ключа набора.
- Состояние забега живёт в `ARunDirector`: вещи и прочитанные записки — по ключу набора (подобранное
  исчезает, выброшенное остаётся, 5.3); у комнаты за каждой дверью свои двери и состояние аномалии.
- Проверка порта: `tools/ue/check_port.py` выгружает из Unreal то же, что `dump.py`, и сравнивает с `golden/`.

## Результаты

Правила (решения автора 13.11): комнату определяет только набор; правильный путь безопасен; аномалию несёт
любое неправильное сочетание. Значимых предметов 12 из 16 (4 на правильном пути, 8 лишних), в комнате кроме
предмета пути лежат ещё 3–4 вещи. Числа — `python3 sim.py --seeds 10000 --first 200001`, сетка рычагов —
в `BALANCE.md`.

Ошибок генератора нет: статическая проверка 0 из 10000, непроходимых по запискам 0 из 10000.

| Игрок | Побед | Урон в среднем | Дверей до победы, медиана (10–90%) |
|---|---|---|---|
| По запискам | 100% | 0 из 4 | 5 (5–5) |
| По запискам, пропуская 30% записок | 100% | 0 из 4 | 5 (5–5) |
| Наугад | 0,0% (не больше 3 из 10000) | 4,00 из 4 | 8 |
| Умный перебор (доп.) | 3,4% | 3,93 из 4 | 11 (8–13) |

Что двигает числа:

- Игрок по запискам проходит ровно за пять дверей и урона не получает: рубка → {L} → {L,K1} → {L,K1,K2} →
  двигательный отсек → рубка.
- Перебор сдерживают три рычага: сколько лишних значимых предметов в забеге, как часто они лежат
  и сколько вещей в комнате. При 5 лишних и 2–3 вещах в комнате он выигрывал 62% забегов.

### Чего симуляция не знает

- Урон — абстракция: аномалия при входе бьёт всегда, одно попадание за вход. Если от части аномалий
  удаётся увернуться, перебор будет выигрывать чаще 3–4%.
- Игрок по запискам здесь идеальный. Живой игрок возьмёт не тот предмет или уронит нужный и попадёт
  в опасную комнату: его потери — только от ошибок.
- Умный перебор — одна конкретная стратегия. Игрок, который догадается, что опасны сочетания,
  а не предметы, может перебирать умнее.
- Время в комнате не моделируется. Пять дверей — это длина забега в дверях, а не в минутах.
- Скафандра, лечения, оружия и противников нет.

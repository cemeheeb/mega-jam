# Рецепты ассетов Singula

По этим текстам ассеты Singula пересобираются с нуля. Здесь только промты и описания. Старые скрипты, картинки, меши Tripo, blend, текстуры и glb не используются. Всё делается заново: картинка по промту, меш Tripo по картинке, модель, развёртка, маски, ArmorPaint, выгрузка.

Рецепт заменяет старые скрипты на Python. В нём всё, что они знали: размеры, детали, способы построения, развёртка, каналы масок, слои ArmorPaint с числами, выгрузка, проверки, подводные камни. Кода в рецептах нет — код каждый раз пишется заново по тексту. Блоки ```text — это промты картинок.

## Как пользоваться

1. Прочитать [pipeline/rules.md](pipeline/rules.md) — правила автора для всех ассетов.
2. Открыть рецепт ассета в [recipes/](recipes/). Промт из раздела «Картинка» отдать автору: он генерирует картинку в Nano Banana, утверждает её в Студии и делает по ней меш в Tripo.
3. Собрать модель по разделу «Модель». Сохранить blend и остановиться: автор смотрит модель в Blender.
4. Развёртка, маски, ArmorPaint, доводка — по рецепту и общему файлу из `pipeline/`, на который он ссылается.
5. Выгрузка — только по прямой просьбе автора. Игра на Unreal Engine 5.8, модели идут в FBX: `SM_<Объект>.fbx` и текстуры `T_<Набор>_*.png`. В Unreal лицо предмета смотрит в +Y, единицы — сантиметры, подвижные детали — отдельные меши, которые собираются в блюпринт. Всё общее — в [pipeline/unreal.md](pipeline/unreal.md), в рецептах — только своё.

## Общие файлы

- [pipeline/rules.md](pipeline/rules.md) — правила автора: ход работы, модель по референсу, эргономика, имена, развёртка, износ, тёмные детали, ArmorPaint.
- [pipeline/unreal.md](pipeline/unreal.md) — выгрузка в Unreal: пути, имена, оси и углы, настройки FBX, подвижные детали, мастер-материал `M_Kit`, импорт и первая проверка.
- [pipeline/kit.md](pipeline/kit.md) — конвейер наборов: построение из примитивов, упаковка, проверка, маски из геометрии, проект ArmorPaint фоном, доводка, FBX на объект.
- [pipeline/kit-layers.md](pipeline/kit-layers.md) — расширенный стек масок и слоёв поверх `kit.md`: царапины, рёбра, подсветка граней, укрытие внутренних сторон.
- [pipeline/atlas.md](pipeline/atlas.md) — цепочка модулей стен и двери: трим-лист, свой атлас 2048 полками, запекание вида и касаний, слои Seams, Dust, Scuffs, Hands, Shoes.
- [pipeline/seamless-texture.md](pipeline/seamless-texture.md) — как сделать картинку бесшовной: поверхность и полосы трим-листа.

## Порядок

Одни ассеты опираются на другие, поэтому сначала:
1. `ship-trim` и `fine-scratches` — на них стоят `wall-columns` и `sliding-door`.
2. `wall-columns` — по её сетке строятся `sliding-door` и ниша под `rack-equipment`.
3. `ventilation` перед `flexible-duct` — воздуховод стыкуется с вентиляцией.

Остальные наборы независимы.

## Открытые вопросы к автору

- **Старый вид или новые правила.** Наборы на `kit.md` и `kit-layers.md`, колонки и дверь сделаны раньше части правил из `rules.md`. Например, там светлая грязь, царапины по всей краске, нет тонкой светлой линии на тёмных рёбрах, цвета слоёв абсолютные. Рецепты описывают старый вид, расхождения отмечены в каждом. Повторять старый вид или собирать по новым правилам?
- **Промты без проверки.** У многих наборов в Студии нет снимка утверждённой картинки. В рецепте тогда стоит промт, собранный из манифеста: им ещё ничего не генерировали.
  - У `flexible-duct` нет описания предмета: форма была с фото автора.
  - Утверждённая картинка `rubber-floor` не совпадает с промтом.
- **Размеры текстур.** Трим-лист сейчас 1024², гайд стиля хочет 2048². Для `rack-equipment` размер текстур в игре не выбран.
- **Ошибки двери.** Две ошибки старой сборки описаны в рецепте, чтобы их не повторить: ободок ручки с обратной стороны створки брал ряды резины, нижняя направляющая заходит в створку без паза.

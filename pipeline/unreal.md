# Выгрузка в Unreal Engine 5.8: FBX

Общие правила выгрузки для всех ассетов. Раньше ассеты выгружались для Godot в glb. Теперь игра делается на Unreal Engine 5.8, а модели передаются в FBX. Рецепты описывают только свои отличия: имена объектов, точки привязки, подвижные детали и особые материалы. Всё общее записано здесь.

Что проверено. Названия опций и их значения по умолчанию взяты из установленных программ: Blender 5.2 LTS (`bpy.ops.export_scene.fbx`) и заголовков Interchange в UE 5.8 (`InterchangeFbxTranslator.h`, `InterchangeGenericMeshPipeline.h`, `InterchangeGenericAssetsPipelineSharedSettings.h`, `InterchangeGenericMaterialPipeline.h`, `InterchangeGenericTexturePipeline.h`). Первым импортирован герой (скелетный меш, 14 ноября), см. «Первый импорт: результат»; статичных мешей ещё не импортировали. Оси, масштаб и повороты подвижных деталей выведены по формулам, поэтому на первом ассете их нужно проверить (раздел «Первый импорт»).

## Пути

- Unreal Engine 5.8: `/Users/Shared/Epic Games/UE_5.8`. Редактор — `Engine/Binaries/Mac/UnrealEditor.app`.
- Проект Unreal — `MegaJam.uproject` в корне репозитория. Ниже `<проект>` — его папка, та, где лежит `.uproject`.
- Файлы для импорта лежат в `<проект>/SourceArt/`, рядом с `Content/`, а не внутри неё. Содержимое `Content/` Unreal отслеживает сам и может импортировать новый PNG или FBX без спроса.
- Корень игры для Студии — `<проект>/SourceArt`: `node core/src/cli.ts validate assets --game <проект>/SourceArt`. Поле `game.directory` в манифесте остаётся прежним, например `environment/common/lamps`. В этой папке лежат FBX и текстуры для импорта, в подпапке `source/` — blend, маски, `.arm`, промежуточные выгрузки ArmorPaint и скрипт выгрузки.
- Куда импортировать в Unreal: `/Game/` плюс `game.directory`, где каждое слово пишется с заглавной буквы и без дефисов: `environment/common/safety-equipment` → `/Game/Environment/Common/SafetyEquipment`.
- Манифест. В схеме Студии поле моделей пока называется `game.glb` («Модели для Godot»), и этап тоже называется `glb`. Схему Студии рецепты не меняют, поэтому пути к FBX пишутся в `game.glb`. Переименовать поле в Студии — отдельная задача.

## Имена

Имя ассета в Unreal берётся из имени файла, поэтому файлы называются по правилам Unreal.

| Что | Файл | Пример |
|---|---|---|
| Статичный меш | `SM_<Объект>.fbx`, где `<Объект>` — имя объекта в Blender как есть | `SM_FireExtinguisherBracket.fbx` |
| Подвижная деталь | тоже `SM_<Деталь>.fbx` по имени её объекта | `SM_ThrustLeverHandle.fbx` |
| Цвет | `T_<Набор>_BaseColor.png` | `T_SafetyEquipment_BaseColor.png` |
| AO, шероховатость, металл | `T_<Набор>_ORM.png` | |
| Нормали | `T_<Набор>_Normal.png` | |
| Свечение | `T_<Набор>_Emissive.png` | |
| Особая текстура набора | `T_<Набор>_<Что>.png` | `T_WallColumns_Grille.png` |
| Экземпляр материала | `MI_<Материал>`, где `<Материал>` — имя материала в Blender | `MI_SafetyEquipment`, `MI_Indicator` |
| Мастер-материал | `M_Kit`, один на проект; `M_KitGlass` для прозрачного, `M_KitSolid` для однотонного | |
| Блюпринт: меши с подвижными деталями, меш со светом | `BP_<Объект>` | `BP_ThrustLever`, `BP_CagedCeilingLamp` |

`<Набор>` — последнее слово `game.directory` в CamelCase: `environment/common/safety-equipment` → `SafetyEquipment`, `environment/bridge/control-console-parts` → `ControlConsoleParts`. Имя коллекции и материала в Blender может отличаться (`Console`, `ControlConsole`, `Collection`) — в Unreal всё равно `<Набор>`.

Исходники для Blender (`source/…`, текстуры Студии вроде `ship-trim_base.png` и `fine-scratches.png`) не переименовываются: в Unreal они не попадают.

Текстура Студии (`kind: texture`), которая идёт в Unreal сама, а не через запекание в атлас, называется `T_<Ассет>_<Канал>.png`, где `<Ассет>` — ID ассета в CamelCase: `fabric-weave` → `T_FabricWeave_Normal.png`.

## Оси и единицы

| | Blender | Unreal |
|---|---|---|
| Единицы | метры | сантиметры |
| Верх | +Z | +Z |
| Система | правая | левая |
| Лицо предмета | −Y (вид спереди Blender) | +Y |

- **Перевод точки.** Blender (x; y; z) м → Unreal (100·x; −100·y; 100·z) см. Ось X общая, Y меняет знак.
- **Старые числа из рецептов в осях Godot.** Godot (x; y; z) м → Unreal (100·x; 100·z; 100·y) см: высота Godot y становится Unreal Z, «от стены» Godot z становится Unreal Y.
- **Настенный предмет.** Стена — плоскость y = 0 объекта. Предмет выступает в −Y Blender, то есть в +Y Unreal.
- **Углы, один поворот.** В Details поле Rotation показывает X = Roll, Y = Pitch, Z = Yaw.

  | Поворот на θ (по правилу правой руки) | Roll | Pitch | Yaw |
  |---|---|---|---|
  | вокруг X Blender или X Godot | θ | | |
  | вокруг Y Blender | | −θ | |
  | вокруг Z Blender (верх) | | | −θ |
  | вокруг Y Godot (верх) | | | −θ |
  | вокруг Z Godot | | θ | |

- **Кватернион.** Blender (x; y; z; w) → Unreal FQuat (−x; y; −z; w). Godot (x; y; z; w) → Unreal (−x; −z; −y; w). Пример: −15° вокруг X Godot (−0,1305; 0; 0; 0,9914) → FQuat (0,1305; 0; 0; 0,9914) → Roll −15°.
- **Масштаб.** У объектов масштаб 1. Если рецепт уменьшает модель при выгрузке, уменьшение применяется к вершинам, а масштаб объекта остаётся 1.
- **Зеркало.** Зеркальная копия в Unreal — масштаб −1 по нужной оси у компонента или актора. Unreal сам разворачивает грани.

Почему так. При экспорте с осями Blender по умолчанию (Forward −Z, Up Y) и импорте с настройками Unreal по умолчанию (Convert Scene включено, Force Front X Axis выключено) сцена переводится обратно в Z вверх, а затем ось Y меняет знак при переходе к левой системе. Лицо предмета можно повернуть в +X флагом Force Front X Axis, но его пришлось бы ставить при каждом импорте. Поэтому флаг не используется: лицо в Unreal смотрит в +Y.

## Подвижные детали

Иерархию узлов, как в glb, статичный меш Unreal не хранит. По умолчанию импорт запекает положение узла в вершины (Bake Meshes включён), и центр каждого меша оказывается в начале сцены FBX. Поэтому:

- Корпус и каждая подвижная деталь — отдельные FBX. Корпус выгружается без детей.
- Начало координат детали — её ось или точка нажатия, как в рецепте. На время выгрузки деталь ставится так, чтобы её начало совпало с началом сцены, без поворота (`matrix_world` — единичная). Её меш выходит в собственных осях детали.
- Сборка — блюпринт `BP_<Объект>`. Корневой компонент — StaticMesh корпуса, подвижные детали — дочерние StaticMesh. Относительные положение и поворот берутся из таблицы рецепта: положение детали в осях родителя и её поворот покоя в Blender, переведённые в Unreal по разделу «Оси и единицы». Движение (ход кнопки, угол рычага) задаётся в блюпринте.
- Корень-пустышка (Empty) в FBX не идёт (`object_types` = MESH). В блюпринте его место — корневой Scene Component (Add → Scene), детали — относительно него. Если начало пустышки совпадает с началом одного из мешей, корнем может быть этот меш.
- В блюпринт можно положить и свет, и коллизию для взаимодействия.

## Выгрузка из Blender

Только по прямой просьбе автора. Скрипт `source/export_<набор_с_подчёркиваниями>.py` каждый раз пишется заново по этому разделу и рецепту. Студия запускает его как `blender -b <blend> --python <скрипт>` из корня игры (`<проект>/SourceArt`). В blend ничего не сохраняется.

1. **Текстуры.** Из `source/export/` (или откуда указывает рецепт), читать и писать как данные (Non-Color), PNG 8 бит RGB. Альфа нужна только там, где её требует рецепт.
   - Если рецепт задаёт размер меньше исходного, уменьшать средним по блокам 2 × 2.
   - Нормали: распаковать (× 2 − 1), нормировать, **инвертировать зелёный канал** (G → 1 − G) и запаковать. Blender и ArmorPaint работают с нормалями OpenGL, а Unreal ждёт DirectX. Файлы в `source/export/` остаются OpenGL: по ним смотрит Blender.
   - Записать в папку набора как `T_<Набор>_BaseColor.png`, `T_<Набор>_ORM.png`, `T_<Набор>_Normal.png`, `T_<Набор>_Emissive.png`. Каналы ORM те же: R — AO, G — шероховатость, B — металл.
2. **Каждый выгружаемый объект** (корень без родителя, а если в рецепте есть подвижные детали — и каждая деталь), по алфавиту. Только объекты коллекции набора: меш Tripo, куски `Reference*`, коллекции `Source` и `Context` не выгружаются никогда.
   - показать (скрытый объект уходит пустым), выделить только его, сделать активным;
   - запомнить `matrix_world` и поставить единичную. Дети без выделения едут следом, но в файл не попадают;
   - если рецепт велит выгрузить объект вместе с неподвижными потомками, то на время выгрузки их копии с применёнными модификаторами (Triangulate тоже) объединяются с копией объекта в один меш (Join), с началом объекта. Иначе Unreal сделает из каждого потомка отдельный Static Mesh: Combine Static Meshes по умолчанию — Do Not Combine. После выгрузки копии удаляются;
   - на время выгрузки заменить материалы во всех слотах временными: Principled без картинок. Материал набора (тот, что несёт текстуры набора) → `MI_<Набор>`; любой другой материал `X` (`Indicator`, `ClearPlastic`) → `MI_X`. По этому имени Unreal находит готовый экземпляр материала, а картинок в FBX нет, поэтому лишние текстуры не создаются. Слоты с одним материалом Unreal сливает в одну секцию сам (Keep Sections Separate выключено по умолчанию);
   - добавить последним в стек модификатор Triangulate с `keep_custom_normals` = True (остальное по умолчанию). Треугольники нужны, чтобы Unreal резал грани так же, как Blender, и касательные совпали с запечёнными. Опция FBX `use_triangles` для этого не годится: она сбивает заданные нормали (проверено в Blender 5.2: отклонение до 27,6° против 0,03° с модификатором);
   - выгрузить FBX с настройками ниже в файл `SM_<Объект>.fbx` в папке набора;
   - убрать модификатор, вернуть материалы и `matrix_world`.
3. **Проверить**, что файлов столько, сколько в рецепте, и что у каждого есть пара в списке `game.glb` манифеста.

### Настройки FBX (Blender 5.2, `bpy.ops.export_scene.fbx`)

| Опция | Значение | Зачем |
|---|---|---|
| `use_selection` | True | только выделенное |
| `object_types` | {'MESH'} | без камер, света и пустышек |
| `apply_unit_scale` | True | |
| `apply_scale_options` | 'FBX_SCALE_UNITS' | 1 м Blender = 100 см Unreal, масштаб узла 1 |
| `axis_forward`, `axis_up` | '-Z', 'Y' (по умолчанию) | Unreal переводит обратно сам |
| `bake_space_transform` | False | экспериментальная опция, не нужна |

| `use_custom_props` | False | свойства вроде `touch` и `travel` в игру не идут |
| `add_leaf_bones` | False | |

## Мастер-материал `M_Kit`

Создаётся в Unreal один раз, при первом импорте, в `/Game/Materials/`. Все наборы используют его экземпляры.

- `BaseColor` — Texture Sample Parameter 2D, тип сэмплера Color → Base Color. Его альфа → Opacity Mask (работает только в режиме Masked).
- `ORM` — Texture Sample Parameter 2D, сэмплер Masks: R → Ambient Occlusion, G → Roughness, B → Metallic. Разумного значения по умолчанию у неё нет, поэтому она есть у каждого набора. Если у набора своей карты нет, скрипт выгрузки пишет однотонную `T_<Набор>_ORM.png` 4 × 4 со значениями материала из рецепта: R = 1, G — шероховатость, B — металл.
- `Normal` — Texture Sample Parameter 2D, сэмплер Normal, по умолчанию `/Engine/EngineMaterials/FlatNormal` → Normal.
- `Emissive` — Texture Sample Parameter 2D, сэмплер Color, по умолчанию чёрная текстура (`/Engine/EngineResources/Black`). Умножить на скаляр `EmissiveStrength` (по умолчанию 1) → Emissive Color.
- Blend Mode — Opaque, Two Sided **включено**. Так было и в glb: экспортёр glTF делал двусторонними все материалы, у которых в Blender выключено отсечение задних граней (а оно выключено по умолчанию), и у многих наборов есть поверхности без толщины. Экземпляр меняет это в Details → Material Property Overrides: Two Sided, Blend Mode = Masked, Opacity Mask Clip Value 0,5.

`M_KitGlass` — для оргстекла и линз: Blend Mode Translucent, векторный параметр `Color`, скаляры `Opacity`, `Roughness`, `EmissiveStrength`.

`M_KitSolid` — для однотонных материалов без текстур (огоньки `Indicator`, кабели): векторный параметр `Color` → Base Color, скаляры `Roughness`, `Metallic`, `EmissiveStrength` (по умолчанию 0); Emissive Color = `Color` × `EmissiveStrength`.

Общие экземпляры, которые нужны нескольким наборам (`MI_Indicator`, `MI_ClearPlastic`), лежат один раз в `/Game/Materials/`. Экземпляры одного набора — в его папке. Имена `MI_` уникальны по всему проекту: импорт ищет их по имени во всём `Content`.

Как в Godot, Ambient Occlusion материала гасит только непрямой свет. Поэтому тени швов по-прежнему рисуются и в базовом цвете (`rules.md`).

Варианты одного набора — отдельные экземпляры: `MI_<Набор>_Off` с `EmissiveStrength` = 0 для погашенных огней. Во время игры свечение меняется через Dynamic Material Instance.

## Импорт в Unreal

Порядок: текстуры → экземпляр материала → FBX. Если импортировать FBX раньше, чем создан `MI_<Материал>`, Unreal создаст обычный материал с этим именем, и его придётся удалить.

1. **Папка.** Content Browser → правой кнопкой по `Content` → New Folder → путь из раздела «Пути».
2. **Текстуры.** В папке: кнопка Import → выбрать PNG набора. Двойным щелчком открыть каждую и проверить в Details:
   - `T_*_BaseColor`, `T_*_Emissive` — Compression Settings: Default, sRGB включён;
   - `T_*_ORM` — Compression Settings: Masks (no sRGB), sRGB выключен;
   - `T_*_Normal` — Compression Settings: Normalmap, Flip Green Channel выключен (зелёный уже инвертирован при выгрузке);
   - текстура с альфой (решётка, декали) — Compress Without Alpha выключен.
3. **Экземпляр материала.** Правой кнопкой по `M_Kit` → Create Material Instance → имя `MI_<Материал>` → перенести в папку набора. Открыть, отметить параметры `BaseColor`, `ORM`, `Normal`, `Emissive`, подставить текстуры набора. Переопределения (Two Sided, Masked) — по рецепту.
4. **FBX.** Кнопка Import → выбрать все `SM_*.fbx` набора. В окне Interchange:
   - FBX Translator: Convert Scene включено, Force Front X Axis выключено, Convert Scene Unit включено (так по умолчанию);
   - Static Meshes: Combine Static Meshes — Do Not Combine (по умолчанию); Collision — по разделу «Коллизии»;
   - Common Meshes: Recompute Normals **выключить** (нормали и острые рёбра из Blender), Recompute Tangents включено, Use MikkTSpace включено;
   - Materials: Import Materials включено, Reuse Existing Materials включено, Search Location — Under Root (по умолчанию Local, то есть только папка набора; тогда общие `MI_` из `/Game/Materials/` не найдутся);
   - Textures: Import Textures выключить;
   - Build Nanite в 5.8 включён по умолчанию. Его оставить, но для мешей с прозрачным материалом (`M_KitGlass`) выключить: Nanite не рисует прозрачное.
5. **Блюпринт сборки** (если в рецепте есть подвижные детали): Content Browser → Add → Blueprint Class → Actor → `BP_<Объект>`. В Components: Add → Static Mesh для корпуса (сделать корнем), затем для каждой детали дочерний Static Mesh. Location и Rotation — из таблицы рецепта.

## Не решено

- Детальная нормаль с мелким тайлом (ткань, кожа) и тайловые материалы (резиновый пол, стёганая обшивка): у `M_Kit` нет ни входа детальной нормали, ни тайлинга. Мастер-материал для них выбрать вместе с автором, когда дойдёт до первого такого ассета.

## Коллизии

- Предметы. По умолчанию Interchange строит простую коллизию 18DOP (Collision включено, тип Convex18DOP). Для мелких предметов этого достаточно.
- Модули с проёмами и нишами (дверь, стены шахты): выпуклая оболочка закроет проём. В Static Mesh Editor → Details → Collision Complexity = Use Complex Collision As Simple. Другой вариант — коробки `UCX_<Объект>_<n>` в Blender. Unreal их узнаёт по имени (Import Collision According to Mesh Name включено по умолчанию), а в FBX они выгружаются вместе с объектом.
- Подвижные детали, через которые проходит игрок (створка двери), — простая коробка, а не 18DOP.

## Свет

Корпуса светильников сами не светят. Источник (Point, Spot или Rect Light) ставится в Unreal в блюпринт светильника или в актор комнаты.

## Первый импорт: что проверить

Это проверка самих правил. Её делают на первом наборе с подвижной деталью, например `command-console-parts` или `door-hatch-controls`.

1. Static Mesh Editor → Details → Approx Size равен размерам из рецепта в сантиметрах, у компонента масштаб 1. Если размер больше в 100 раз или меньше в 100 раз, сверить `apply_scale_options` и Convert Scene Unit.
2. Начало меша (пивот) — точка привязки из рецепта.
3. Лицо смотрит в +Y Unreal: зелёная стрелка гизмо в окне меша.
4. Подвижная деталь в `BP_` встала на место по таблице. Её поворот на +10° по оси движения идёт в ту сторону, что в рецепте. Если нет — исправить таблицу перевода углов здесь и во всех рецептах.

## Первый импорт: результат

14 ноября 2026, герой `SK_Engineer` (скелетный меш, `characters/engineer`). Импорт делался через MCP редактора
скриптами `tools/ue/kit_materials.py` и `tools/ue/import_engineer.py`, а не через окно Interchange.

- **Единицы.** `SkeletalMeshTools.import_file` идёт через старый `FbxFactory` (в журнале `LogFbx`), а у него
  Convert Scene Unit выключен. Метровый FBX (`FBX_SCALE_UNITS`, единица сцены 1 м) встал в 100 раз меньше.
  Поэтому скрипт героя пишет файл сразу в сантиметрах: на время выгрузки единица сцены 0,01 м, меши ×100,
  скелет манекена и так в сантиметрах. `UnitScaleFactor` в файле 1, при любом импортёре размер верный.
  Для статичных мешей через `StaticMeshTools.import_file` скорее всего то же самое — проверить на первом наборе.
- **Оси.** Лицо в +Y Unreal, как в таблице выше; поворот не понадобился.
- **Скелет.** Корень FBX — сам объект арматуры `root` (тип узла Null по умолчанию), пустышка-родитель не выгружается.
  Оси костей по умолчанию (`primary_bone_axis` Y, `secondary_bone_axis` X) — те же, с какими манекен импортирован
  в Blender, поэтому анимации шаблона встают без перенастройки. Импортёр пишет «Not valid bind pose… Recreating bind
  pose succeeded»: поза в файле — поза покоя, на результат не влияет.
- **Материалы.** Импорт без материалов (`import_materials` = False), слоты называются по временным материалам
  `MI_<Материал>`, экземпляры ставит скрипт. Для параметра `ORM` в `M_Kit` нужна текстура по умолчанию с типом
  Masks — в движке такой нет, поэтому `/Game/Materials/T_Kit_DefaultORM` (4 × 4: AO 1, шероховатость 0,5, металл 0).
  У `M_Kit` и `M_KitSolid` включены `bUsedWithSkeletalMesh` и `bUsedWithMorphTargets`.
- **Повторный импорт.** Инструменты импорта MCP не перезаписывают существующий ассет («already exists»),
  настоящего реимпорта среди них нет. Скрипт удаляет меш и импортирует заново. Удаление обнуляет ссылки на меш
  у акторов уровней (14 ноября так опустели три героя на проверочном уровне): после импорта их надо вернуть.
  Ассеты, на которые ссылается код по пути (`ConstructorHelpers`), от этого не страдают.
- **Формы лица (morph targets) и нормали.** У `FbxFactory` по умолчанию `bImportMorphTargets` = False
  и `normalImportMethod` = ComputeNormals, а у инструмента MCP таких опций нет. Скрипт перед импортом ставит
  `bImportMorphTargets` = True и `FBXNIM_ImportNormals` в объектах настроек по умолчанию
  (`Default__FbxSkeletalMeshImportData` и `Default__FbxImportUI:SkeletalMeshImportData`). После перезапуска
  редактора они сбрасываются. Проверено тестовой формой: без этого форма теряется, с этим доходит.
- **Без Triangulate.** Если на меше включён любой модификатор, кроме Armature, экспортёр FBX берёт вычисленный
  меш, а в нём нет форм (Blender #104714). У героя нет карты нормалей, поэтому треугольники ему не нужны
  и модификатор не ставится. Набору с картой нормалей и формами пришлось бы триангулировать сам меш.

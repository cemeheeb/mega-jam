# Конвейер наборов (kit): Blender → маски → ArmorPaint → FBX для Unreal

Общие шаги для набора мелких объёмных деталей. Набор — несколько объектов с одной развёрткой на всех, одним материалом и тремя общими текстурами. По этим шагам целиком сделаны `safety-equipment` и `ventilation`. `flexible-duct` — вариант с тайловой текстурой: отличия в его рецепте. Поздние наборы (`lamps`, `command-console-parts`, `door-hatch-controls`, `rack-equipment`, `crew-items`) строятся так же и добавляют слои и маски — см. `kit-layers.md`.

Рецепт набора даёт объекты, их детали и размеры, особые канавки и узоры в масках, переопределения материалов и отличия от этих шагов. Всё общее — здесь. Общие правила автора для всех ассетов — `rules.md`.

## Соглашения

- Единицы — метры, сцена METRIC, масштаб 1. В рецептах размеры в мм.
- Blender: Z вверх. У настенного объекта стена — плоскость y = 0 объекта, предмет выступает в −Y.
- Unreal (сантиметры, Z вверх, левая система): точка Blender (x; y; z) м становится (100·x; −100·y; 100·z) см. Лицо настенного предмета смотрит в +Y Unreal, спина лежит в плоскости Y = 0. Подробно, с углами — [unreal.md](unreal.md).
- Коллекция набора — CamelCase по имени набора (`SafetyEquipment`), в ней только объекты набора. Объекты — CamelCase по назначению, данные меша — `<Имя>.Mesh`. Один материал на набор с тем же именем, что у коллекции.
- У объектов поворот 0 и масштаб 1. Начало координат объекта — точка привязки в игре (своя у каждого объекта, в рецепте). Положение объекта в сцене Blender — место его куска в ряду Tripo.
- Файлы в игре: папка набора `environment/<биом>/<набор>/` в `<проект>/SourceArt/` — `SM_*.fbx` и текстуры `T_<Набор>_*` 1024 для импорта в Unreal; `source/` — blend, FBX для ArmorPaint, маски 2048, `.build.c`, `.arm`, `export/`, скрипт выгрузки.
- Промежуточные файлы (поля растеризации, маска «внутри», картинка проверки) — во временной папке сессии.
- Картинки, которые пишет Blender: в массиве пикселей строка 0 — низ картинки, то есть v = 0. Маски пишутся как данные (флаг is_data, цветовое пространство Non-Color), PNG 8 бит, RGB, альфа 1. Сторонний инструмент (PIL и т. п.) должен переворачивать строки.

## Шаг 1. Картинка, меш Tripo, обмер

- Картинка. Промт — из рецепта набора. Ключа Tripo API нет: генерирует автор в Nano Banana и приносит картинку в Студию («Картинки» → «Из Загрузок»). Дальше — только после утверждения.
- Меш Tripo импортируется в Blender. В `ventilation` он лежал так: весь ряд по длинной стороне 1,0 м, стоит на Z = 0, по центру по X и Y, повёрнут на 90° вокруг X, как пришёл из glb. Этот масштаб приняли за настоящий: размеры деталей сняты с меша как есть. Деталь, которая выходит явно не того размера, масштабируется отдельно, причина пишется в notes (в рецептах: фонарь × 0,75, секция с заслонкой × 1,13).
- Меш делится по несвязанным частям (Separate by Loose Parts). Части одного предмета собираются в объект `ReferenceA`, `ReferenceB`… в коллекции `Source`, скрытой от рендера. Новый объект ставится туда, где стоит его кусок.
- Обмер: границы каждого куска, профили (радиус по высоте у тел вращения, контур у плоских деталей). Строить по числам.
- Правило автора. Каждая деталь референса строится как есть: не заменять её более простой или другой. Свобода — в чистой сетке и развёртке, не в дизайне. Если часть референса физически абсурдна, строится то, что было бы у настоящего предмета, и отступление пишется в notes. Артефакты генерации (ямки, наплывы) выбрасываются; просто необычная деталь остаётся.
- Меш Tripo не идёт ни в FBX для ArmorPaint, ни в FBX для игры. В итоговом blend его можно убрать или держать скрытым вне коллекции набора.

## Шаг 2. Построение из примитивов

Каждая поверхность строится многоугольниками сразу с развёрткой. UV пишутся в метрах — настоящими длинами там, где поверхность развёртывается точно: плоскость, цилиндр, конус, полоса. Автоматического unwrap нет. Поэтому плотность текселя после упаковки одна на весь набор, а растяжения нет или почти нет.

### Как устроен построитель

У каждого объекта — список граней. Грань — точки в своей системе координат детали, переведённые матрицей 4 × 4, UV в каждом углу (метры), номер острова, зона и флаг «мягкая». Номера островов свои у объекта: каждый примитив берёт себе следующие номера.

Системы координат детали:
- сдвиг (x; y; z);
- рамка: локальные оси X, Y, Z — заданные векторы мира, плюс начало;
- «стена»: локальный X = X мира, локальный Y = Z мира, локальный Z = −Y мира. Контур рисуется в плоскости XZ мира, выдавливание идёт от стены (−Y). Без начала — начало на стене, в начале объекта;
- остальные рамки — в рецепте набора.

Скруглённый прямоугольник (контур): ширина w, высота h, радиус угла R, seg отрезков на угол. Точки идут против часовой, если смотреть с +Z. Углы по порядку: (+x; −y), (+x; +y), (−x; +y), (−x; −y); каждый угол — seg + 1 точек от его начала (−90°, 0°, 90°, 180°) через 90°/seg. При seg = 0 — четыре вершины прямоугольника. Параметр «начало» сдвигает первую точку по кругу: так выбирается, где ляжет шов боковой полосы.

Четверть скругления радиуса b — три уровня через 30°. Уровень — пара (отступ внутрь; высота). Для торца сверху на высоте z: (0,134b; z − 0,5b), (0,5b; z − 0,134b), (b; z). Для торца снизу на высоте z — в обратном порядке: (b; z), (0,5b; z + 0,134b), (0,134b; z + 0,5b). Уровень боковой стенки (0; z ∓ b) пишется в профиль отдельно. Шаг 30° держит рёбра скругления гладкими (меньше 35°).

### Примитивы

**Призма (по уровням).** Скруглённый прямоугольник w × h (R, seg) в плоскости XY детали, протянутый вдоль +Z через профиль уровней (отступ d; высота z). Уровень — контур, сжатый на d: w − 2d, h − 2d, радиус R − d, то же число точек. Грани — четырёхугольники между соседними уровнями; дно — многоугольник первого уровня, смотрит в −Z; верх — многоугольник последнего уровня, смотрит в +Z. Дно и верх можно не строить. Зона одна или три: дно, бок, верх. R ≤ 0 — острые углы. Развёртка — три острова, границы задают номера уровней split0 и split1:
- остров дна: дно и все пояса ниже split0. Пояс раскладывается вокруг дна как контур, сжатый на (d первого уровня − длина профиля от первого уровня до этого). Скос или скругление ложится вокруг торца своей настоящей длиной. По x остров отражён (u = −x), чтобы дно не читалось зеркально;
- остров бока: пояса от split0 до split1 — одна прямая полоса. u — длина по периметру контура с отступом 0 от первой точки, v — длина профиля от split0;
- остров верха: пояса от split1 и верх — так же, как дно, от последнего уровня, без отражения.
По умолчанию split0 = 0, split1 = последний уровень: торцы отдельно, весь бок — полоса.

**Тело вращения.** Многогранник из n граней вокруг оси Z детали. Точки по кругу — под углами a0 + i · 360°/n; по умолчанию a0 = 90° (первая точка на +Y детали). Профиль — список отрезков (r; z); каждый отрезок профиля — свой остров со своим способом развёртки и своими зонами по участкам. Наружу смотрит сторона справа от направления обхода профиля в плоскости (r вправо, z вверх): профиль наружной стенки идёт вверх. Способы:
- полоса: прямая развёртка. u = i × хорда, хорда = 2 · r_оп · sin(180°/n), r_оп — заданный радиус или наибольший r отрезка; v — длина профиля от начала отрезка. Точно на цилиндре. Длинную полосу можно разрезать по кругу на k островов (в этих наборах не нужно);
- кольцо: плоское кольцо или диск, развёртка в полярных координатах. Вариант «начало»: ρ = r первой точки + длина профиля до точки, угол −i · 360°/n — для кольца, идущего от оси наружу (дно, смотрит вниз). Вариант «конец»: ρ = r последней точки + оставшаяся длина профиля, угол +i · 360°/n — для кольца, идущего к оси (верх). UV = (ρ cos угла; ρ sin угла). Точно на плоском кольце; наклонный участок в том же отрезке развёртывается как продолжение кольца, с небольшим растяжением;
- конус: ровно две точки, точная развёртка граненого усечённого конуса. k = |r1 − r0| / длина образующей; угол грани на развёртке β = 2 · asin(k · sin(180°/n)); ρ = r / k (расстояние до вершины конуса по образующей); UV = (ρ cos(±iβ); ρ sin(±iβ)), знак «+», если конус сужается (r1 < r0), иначе «−».
Участок, у которого один радиус 0, даёт один n-угольник на другом радиусе; оба радиуса 0 — пропуск. Отдельных крышек нет: закрытый торец пишется кольцом до r = 0.

**Плита.** Многоугольник (x; z) в плоскости XZ детали, выдавленный вдоль Y детали симметрично: толщина w, от −w/2 до +w/2. Многоугольник сначала приводится к обходу против часовой. Обе грани лежат на одном острове с UV = (x; z): задняя точно на передней, текстура с двух сторон одна. Торец — одна прямая полоса из точных прямоугольников: u — длина по периметру, v = 0…w.

**Полоса.** Гнутая плоская полоса: средняя линия в плоскости XZ детали (открытая или замкнутая), ширина w вдоль Y детали, толщина t. Обе стороны смещены на ±t/2 со стыками «на ус»: вектор сдвига = (n1 + n2) / (1 + n1 · n2), n — левые нормали соседних отрезков. Сторона A — слева от направления обхода (+t/2). Остров A: сама сторона (u — длина по A, v = 0…w), обе узкие кромки, приклеенные к ней (v от −t до 0 и от w до w + t), и у открытой полосы — оба торца (u от −t до 0 и от конца до конца + t). Сторона B — свой остров (u — длина по B). Зону стороны B можно задать отдельно.

**Колено.** Круглая труба радиуса r из n граней по ломаной со стыками «на ус». Каждый отрезок — цилиндр, срезанный биссекторными плоскостями стыков; точка кольца на стыке — сечение предыдущего отрезка, спроецированное на плоскость стыка. Опорный вектор `up` проецируется поперёк первого отрезка и переносится по ломаной поворотом от направления к направлению. Развёртка точная: u = k × хорда (2r · sin(180°/n)), v — расстояние точки вдоль оси отрезка от его середины. Острова: первый отрезок — свой, последний — свой, все средние — один общий (одинаковые средние отрезки ложатся друг на друга).

**Проволока (трубка по пути).** Круглая проволока радиуса r из n граней по ломаной, открытой или замкнутой, стыки как у колена. Начальная рамка: `up` = +Z, а если первый отрезок почти вертикален (|z| ≥ 0,9) — +X. u = k × хорда, v — длина вдоль проволоки. Торцы (по желанию) — общий остров с полярной UV (r cos; r sin). Флаг «мягкая»: все рёбра между её гранями гладкие.

**Пластина с отверстием.** Плоская грань на высоте z между выпуклым контуром (против часовой) и круглым отверстием радиуса ρ посередине. Для каждой точки контура — точка на окружности отверстия под тем же углом, между ними четырёхугольники. UV = (x; y): с номером острова верха призмы пластина продолжает этот остров.

**Копия.** Повторяет уже построенные грани через матрицу. UV и острова те же: копии лежат на оригинале в атласе и делят тексели. Если матрица зеркалит, порядок точек и UV обращается.

**Масштаб детали.** Все точки и все UV умножаются на одно число. Плотность не меняется. Так правится деталь референса не того размера.

### Сборка меша

- Старый объект с тем же именем и его меш удаляются. Новый меш — `<Имя>.Mesh`.
- Каждая грань добавляется со своими вершинами; потом вершины ближе 0,02 мм сливаются.
- Атрибуты граней (целые, FACE): `zone` и `island`. UV-слой `UVMap`.
- Шов: ребро не ровно у двух граней, или у граней разные острова, или UV на любом конце ребра различаются (больше 10⁻⁶).
- Тени: все грани гладкие (smooth). Ребро острое (`sharp_edge`), если угол между гранями больше 35° и не обе грани мягкие. Значит, скругления шагом 30° и цилиндры из 12 и более граней гладкие, шестигранники и коробки острые.
- Один материал набора; объект — в коллекции набора на своём месте.
- После сборки вывести по объекту число граней, треугольников, островов и размеры — сверить с рецептом.

## Шаг 3. Упаковка

1. Предварительная раскладка. По объектам в порядке коллекции, по островам в порядке номеров: рамка UV острова ставится к курсору. Ряд шириной 2,0 м, зазор 0,02 м между островами и между рядами (новый ряд — выше на высоту ряда + 0,02). Затем все UV делятся на 2,2. Это только для того, чтобы всё легло в 0…1 без наложений.
2. Выделить все объекты коллекции, режим правки, выделить всё, UV → Pack Islands: UDIM source — ближайший (Closest UDIM); поворот включён, способ Cardinal (только 90°: прямые полосы остаются строго горизонтальными или вертикальными); масштаб включён; слияние наложенных (Merge Overlapping) включено — копии остаются одним островом; отступ — доля (Fraction), 0,004; форма Concave.
3. В живом Blender оператору нужен контекст окна с 3D-видом (override окна, области VIEW_3D и её региона WINDOW). Фоном (`blender -b`) он работает и без этого.
4. Повторяющиеся детали на виду — клавиши, тумблеры, всё, что глаз сравнивает рядом, — копируются со своими островами (`copy_own` в `navigator_build.py`). Иначе слияние наложенных кладёт их в одно место атласа, и у всех одинаковые царапины (замечание автора 14.11). Острова копий делить можно только там, где разницы не видно. Детали, на которые смотрят вблизи, получают больше текселей: у пульта навигатора плиты, клавиши и тумблеры ×2,5 (`PANEL_UV`, развёртка умножается при сборке). Упаковка сохраняет относительный масштаб островов, поэтому остальное становится реже: 598 → 511 px/м.
5. Упаковка масштабирует все острова одинаково: плотность одна на набор. Получилось: `safety-equipment` — 2112 px/м на 2048 (тексель 0,47 мм), `ventilation` — 1231 px/м (0,81 мм).

Правила автора: мелкие одинаковые детали (болты, ламели, кольца, защёлки) делят один остров, а клавиши и тумблеры — нет (пункт 4); прямые полосы лежат строго по осям.

## Шаг 4. Проверка развёртки

Растеризовать треугольники UV всех граней на 2048 (центры текселей, проверка по барицентрическим координатам). Для каждого треугольника — якобиан перехода UV → 3D и его сингулярные числа σ1 ≥ σ2. Масштаб — медиана σ1 (метров на единицу UV). Растяжение треугольника = max(|σ1 / масштаб − 1|; |σ2 / масштаб − 1|). Вывести:
- метров на единицу UV и px/м на 1024 и 2048;
- долю площади (по площади в 3D) с растяжением больше 0,1 %, 1 %, 5 %, 15 % и худшее растяжение;
- покрытие атласа;
- наложение: тексели, которые заняты двумя разными островами (пара «объект, остров»). Должно быть 0. Копии — один остров, их наложение не считается;
- рамку всех UV (внутри 0…1) и число островов;
- наименьший зазор между разными островами: наименьшее r от 1 до 39 px, при котором у текселя одного острова есть тексель другого со сдвигом (0; r), (r; 0), (r; r) или (r; −r). Отступ 0,004 даёт около 8 px на 2048;
- картинку `uv.png` 2048: фон (70; 20; 90), острова цветом зоны, швы тёмные (20; 20; 20).

Растяжение допустимо только на сплющенных наклонных участках колец и на поясах скруглений внутри боковой полосы призмы.

## Шаг 5. Растеризация

На входе — объекты коллекции, атлас 2048. Объект получает номер по порядку в коллекции.

1. Каждая грань триангулируется в UV (триангуляция многоугольника, например `mathutils.geometry.tessellate_polygon`) и растеризуется. Тексель берётся, если его центр внутри треугольника. Ещё берутся тексели в пределах примерно 0,75 px снаружи треугольника (запас по барицентрическим координатам e = 0,75 / √(удвоенная площадь треугольника в px²)), если их ещё не занял треугольник строго.
2. На тексель пишутся: владелец (номер объекта, −1 — пусто), зона, положение в 3D в координатах объекта (барицентрическая интерполяция) и «скруглённость» грани.
3. Скруглённость грани — наибольшая по её рёбрам. Учитывается ребро ровно двух граней, гладкое, с углом не меньше 8°. Радиус R = (средняя площадь двух граней) / длина ребра / угол в радианах. Скруглённость = clamp((25 мм − R) / (25 мм − 6 мм); 0; 1): 1 при R ≤ 6 мм, 0 при R ≥ 25 мм. Так тонкая проволока и скругления до 6 мм получают ровный износ по всей поверхности.
4. Точки рёбер для каждого объекта: точки через 0,5 мм по каждому ребру (середины n = длина / 0,5 мм кусков, хотя бы одна):
   - ребро открытое (у него одна грань или больше двух) — полость;
   - гладкое ребро — пропуск;
   - острое ребро с отрицательным углом (вогнутое) — полость, с положительным (выпуклое) — износ.
   Для каждого объекта — дерево поиска ближайшей точки (`mathutils.kdtree`) по износу и по полостям.
5. Поля расстояний. На каждом втором текселе (чётные x и y) — расстояние в 3D от положения текселя до ближайшей точки износа и до ближайшей точки полости своего объекта; если точек нет — 0,05 м. Остальные тексели заполняются за 4 прохода: среднее уже заполненных соседей из 8 того же объекта.
6. Сохранить во временный файл: владелец, зона, положение, расстояния, скруглённость. Проверка: незаполненных текселей 0.

Известный недостаток этого шага — в «Подводных камнях».

## Шаг 6. Маски

Четыре PNG 2048 RGB как данные в `source/` и маска «внутри островов» во временной папке.

| Файл | R | G | B |
|---|---|---|---|
| `<набор>_id.png` | бит 1 материала | бит 2 | бит 3 |
| `<набор>_masks.png` | edge — износ | cav — полость | высота: 0,5 + H / 2 мм, обрезано в 0…1 (0,5 — ровно, 0 — −1 мм, 1 — +1 мм) |
| `<набор>_noise.png` | шум 22 /м (ячейка ≈ 45 мм) | шум 110 /м (≈ 9 мм) | шум 520 /м (≈ 2 мм) |
| `<набор>_relief.png` | нормаль X | нормаль Y | нормаль Z — касательное пространство, OpenGL (Y вверх) |

Высота H в метрах = канавки и швы (отрицательные, свои у набора) + узоры (накатка, плетение — свои у набора). Канавка вдоль линии: высота = −глубина × (1 − smoothstep(плато; полуширина; расстояние до линии)): полная глубина в пределах плато, ноль на полуширине. В рецептах канавка пишется как «полуширина / глубина / плато».

Карта материалов: бит канала = 1, если значение ≥ 0,5. Восемь материалов:

| Биты RGB | Имя в слоях | Материал |
|---|---|---|
| 100 | paint | белая краска по металлу |
| 010 | metal | голый алюминий |
| 001 | dark | графитовый пластик |
| 011 | lens | бирюзовое стекло, линза (у `flexible-duct` — подкладка) |
| 110 | rubber | графитовая резина рукоятки |
| 101 | orange | оранжевая краска |
| 111 | plastic | белый матовый пластик |
| 000 | web | оранжевая тканая лента |

По умолчанию из зон: white → 100, aluminium → 010, graphite → 001, orange → 101, teal → 011. Рецепт набора переопределяет часть.

Износ (R) = max(1 − smoothstep(0; 3 мм; расстояние до ребра износа); 0,6 × скруглённость).
Полость (G) = max(0,9 × (1 − smoothstep(0; 5 мм; расстояние до ребра полости)); clamp(−канавки / 0,6 мм; 0; 1)); затем max с добавочной полостью из рецепта.

Шум. Точка шума — положение текселя в координатах объекта плюс положение объекта в сцене: шум не рвётся на швах развёртки и свой у каждого объекта. Шум значений на целой решётке: хеш ячейки (ix; iy; iz) — n = (ix · 73856093) xor (iy · 19349663) xor (iz · 83492791); n = (n xor (n сдвиг вправо на 13)) × 1274126177; значение = ((n xor (n сдвиг вправо на 16)) and 65535) / 65535. Трилинейная интерполяция с весами 3t² − 2t³. Фрактальный шум частоты f со сдвигом s = (v(p · f + s) + 0,5 · v(p · 2,03f + s + 17,3) + 0,25 · v(p · 4,1f + s + 41,7)) / 1,75. Каналы: f = 22, s = 3,1; f = 110, s = 9,4; f = 520, s = 5,7 (f — в 1/м). Среднее около 0,5, разброс (σ) около 0,11–0,12. Точная последовательность значений не важна, важны частоты.

Карта нормалей. Размер текселя tm — медиана расстояния в 3D между соседними по горизонтали текселями одного объекта (вывести; у `safety-equipment` ≈ 0,47 мм). Градиент H вдоль x и y картинки: центральная разность, если оба соседа того же объекта; односторонняя, если один; 0, если ни одного. Делится на tm и обрезается в ±2. Нормаль = нормировать(−gx; −gy; 1), затем × 0,5 + 0,5. Вне островов — (0,5; 0,5; 1).

Расширение за края островов: каждая карта растёт наружу копированием от 4 соседей — карта материалов на 6 px, остальные на 12 px. Маска «внутри» (тексели островов) сохраняется для доводки. Вывести среднее износа и полости по островам для сверки.

### Маска потёртостей `_scuffs.png`

Потёртости, царапины и сколы рисуются не шумом, а текстурами износа из Singula. Копии лежат в `SourceArt/environment/common/fine-scratches/fine-scratches.png` и `common/weathering/weathering.png`, образец каждой около 1 м. Отдельный скрипт после шага 6, пример — `tools/blender/kit/navigator_scuffs.py`, фоном: `blender -b --factory-startup --python <скрипт> -- <SP>`.

| Канал | Что |
|---|---|
| R | где предмет трут. Только зоны, которые отметил автор, с плавными краями; вне зон 0. Задаются по положению текселя, у каждого набора свои. На отдельном материале канал может значить другое: у пульта навигатора на мате это полировка от предплечий |

Раскладка — по главной оси нормали грани в координатах объекта: лицо — по x и z, бок — по y и z, верх — по x и y. Значение читается по всему текселю: среднее 3 × 3 точек через треть текселя. Если пиксель текстуры больше чем вдвое мельче текселя, текстура сперва уменьшается блоками 2ⁿ.
- Царапины кладутся ячейками в одну плитку: у каждой ячейки свой случайный сдвиг и поворот на четверть, две сетки со сдвигом в полъячейки смешиваются «шатром», чтобы не было повтора.
- `weathering` бесшовная, но её полосы размером с ячейку: повёрнутые ячейки читаются квадратами. Поэтому она просто повторяется, со своим сдвигом на лицо, бок и верх.
- На уплотнённых деталях (панель) обе текстуры кладутся мельче — плитки × 0,4. Плотность для 3 × 3 и уменьшения текстуры берётся своя.

## Шаг 8. Проект ArmorPaint

Проект строится фоном из FBX и скрипта сборки (как — в разделе «ArmorPaint фоном»). Перед сборкой старый `.arm` удаляется.

Ассеты импортируются в порядке: `_id` (индекс 0), `_masks` (1), `_noise` (2), `_relief` (3), `_scuffs` (4).

Слои снизу вверх: `Layer 1` (создаётся сам при импорте меша, остаётся), Base, Relief, Scuffs, Scratches, Chips, Edge wear, Grime. Всего 8.

Процедурного шума в слоях нет — решение автора 14.11: шум читался облачными пятнами. Цвет и шероховатость каждого материала ровные. Там, где в таблицах ниже стоят n1, n2, n3, берётся n = 0,5. `_noise.png` по-прежнему импортируется, чтобы номера ассетов не сдвигались, но к шейдерам не подключается. Узор износа даёт только `_scuffs`.

Каждый слой, кроме Relief, — заливка своим материалом с одним узлом SHADER_GPU. Вход узла — три картинки: Id (ассет 0), Masks (1), Scuffs (4), у каждой цветовое пространство Linear. Выходы: Color и добавленные Opacity, Occlusion, Roughness, Metallic, связаны с входами 0–4 узла OUTPUT_MATERIAL_PBR. У материала и у слоя выключены нормаль, высота, эмиссия, подповерхностное рассеяние (`paint_nor`, `paint_height`, `paint_emis`, `paint_subs`; у слоя ещё `paint_nor_blend`, `paint_height_blend`). Цвет, непрозрачность, затенение, шероховатость и металл включены.

### Общее начало текста шейдера

Картинка на входе SHADER_GPU приходит раскодированной из sRGB, поэтому каждое значение кодируется обратно: x = clamp(1,055 · max(x; 0,0001)^(1/2,4) − 0,055; 0; 1). Так кодируются: edge, cav, hgt (каналы Masks) и touch, scr, wth (каналы Scuffs).

Материалы: r = step(0,5; id.r), g = step(0,5; id.g), b = step(0,5; id.b).
- paint = r(1 − g)(1 − b); metal = g(1 − r)(1 − b); dark = b(1 − r)(1 − g); lens = gb(1 − r);
- rubber = rg(1 − b); orange = rb(1 − g); plastic = rgb; web = (1 − r)(1 − g)(1 − b).
- rel = (hgt − 0,5) × 2 — высота от −1 до 1 (то есть ±1 мм).

### Base

- groove = clamp(−1,8 · rel; 0; 1) × (1 − rubber) × (1 − web).
- Цвет = сумма по материалам (цвет × множитель), затем × (1 − 0,6 · groove).
- Непрозрачность 1. Затенение = 1 − 0,45 · cav − 0,3 · groove. Металл = metal.

| plastic | (0,905; 0,898; 0,872) | 0,965 + 0,07 · n1 | 0,50 + 0,10 · n2 |
| metal | (0,725; 0,737; 0,753) | 0,96 + 0,08 · n3 | 0,32 + 0,06 · n3 |

| orange | (0,949; 0,416; 0,129) | 0,96 + 0,08 · n1 | 0,40 + 0,08 · n2 |

У резины и ленты множитель от высоты: накатка и плетение читаются цветом.

### Relief

Только карта нормалей из `_relief.png`. Материал: узел TEX_IMAGE (ассет 3, Linear) прямо во вход 5 (Normal Map) узла OUTPUT_MATERIAL_PBR. У материала включена только непрозрачность (`paint_opac`), выключены цвет, затенение, шероховатость, металл, высота, эмиссия, рассеяние. У слоя то же, плюс включена нормаль (`paint_nor` = да), `paint_nor_blend` = нет, `paint_height_blend` = нет.

Числа по материалам у каждого набора свои, в его `<набор>_gen_build.py`. Ниже — устройство слоёв на примере пульта навигатора (`navigator_gen_build.py`).

### Scuffs — потёртые полосы (`weathering`)

- rub = smoothstep(0,05; 0,20; wth). Непрозрачность = rub × touch × вес материала.
- Веса: краска 0,3; тёмный пластик плит 0,65 — на чёрном потёртость видна лучше; клавиши 0,35 — при большем весе верх клавиш в пятнах «под камень»; оранжевый 0,25; сталь 0,35.
- Цвет: краска на 10 % серее; тёмные пластики светлее основы. Шероховатость краски ниже (0,36) — затёрта до глянца; у пластика выше (0,5) — мутная.

### Scratches — царапины (`fine-scratches`)

- w = smoothstep(0,02; 0,3; scr); k = w × touch. Непрозрачность = k × (0,4 краска и оранжевый; 0,9 тёмный пластик; 0,85 клавиши; 0,8 сталь).
- На белой краске царапина на 10 % серее и глянцевая (шероховатость 0,29): видна в отражении, а не цветом. На чёрном пластике — светлая матовая линия (0,27 при основе 0,095; шероховатость 0,62). На стали — светлее и глаже.
- До металла не стирается: на тонких линиях в 1–2 текселя голый металл рвётся в точки.

### Chips — сколы (`weathering`, яркие пятна)

- chip = smoothstep(0,55; 0,85; wth). Непрозрачность = chip × touch × 0,5 × (0,9 краска и оранжевый; 0,8 пластик).
- Цвет на краске (0,74; 0,75; 0,76), металл 0,8, шероховатость 0,38; на пластике (0,30; 0,305; 0,315).

### Полировка от рук (в Base)

- polish = touch × (1 − edge): верх клавиш и плит залоснён пальцами, кромки нет. Шероховатость клавиш 0,38 − 0,14 × polish, плит 0,44 − 0,08 × polish.
- Мат: в его зоне touch — полировка от предплечий. Шероховатость 0,81 − 0,5 × touch. Цвет lerp((0,215; 0,220; 0,228); (0,165; 0,173; 0,190); touch): в середине глянцевый и глубже по цвету, к краям матовее и бледнее, граница плавная.

### Edge wear — износ кромок

- wear = smoothstep(0,8; 1,05; edge): ровная полоса, без шума.
- Непрозрачность = wear × вес материала. В зоне touch клавиши и плиты стёрты сильнее: вес × (1 + 0,4 · touch), цвет светлее. Затенение 1. Металл = 0,5 × (paint + orange) + metal.

### Grime — грязь

- dirt = clamp(cav × (0,8 + 0,5 · touch на клавишах, плитах и стали); 0; 1): только в полостях, без пятен. В зоне касаний между клавишами набивается пыль.

Слой-заливка ложится на нижние по своей непрозрачности по каждому включённому каналу. У верхних слоёв затенение равно 1, поэтому там, где они плотные, они ослабляют затенение полостей из Base. Так было.

## Шаг 10. Доводка и сохранение

Поля между островами. ArmorPaint пишет заливки только внутри островов; в полях остаётся серый `Layer 1`, а края островов бывают прокрашены не целиком.
1. Ядро = тексели «внутри», у которых все 4 соседа тоже «внутри» (маска сжата на 1 px: крайний ряд острова перезаписывается).
2. Для `_base`, `_orm`, `_nor` из `source/export`: загрузить как Non-Color; от ядра нарастить на 24 px копированием от 4 соседей; что осталось дальше — `_base` и `_orm` — среднее по ядру, `_nor` — (0,5; 0,5; 1). Записать поверх тех же файлов как данные.

Материал набора в Blender:
1. Удалить все узлы, кроме Principled BSDF и Material Output.
2. Три узла Image Texture: картинки `<Материал>_base` (sRGB), `<Материал>_orm` (Non-Color), `<Материал>_nor` (Non-Color), путь относительный — `//export/<набор>_base.png` и т. д.
3. base → Base Color. orm → Separate Color: G → Roughness, B → Metallic; R (затенение) в Blender никуда не подключается — в Unreal его читает `M_Kit`. nor → Normal Map (касательное, UVMap) → Normal.
   Старые наборы подключали R к группе `glTF Material Output` для экспортёра glTF; для FBX она не нужна.
4. Сохранить blend в `source/<набор>.blend`.

## Шаг 11. Выгрузка FBX

Только по явной просьбе автора. Всё общее — в [unreal.md](unreal.md), раздел «Выгрузка из Blender». Скрипт пишется заново и лежит в `source/export_<набор_с_подчёркиваниями>.py`; Студия запускает его как `blender -b <blend> --python <скрипт>` из корня игры. Для набора он делает:

1. Текстуры. Для `_base`, `_orm`, `_nor` из `source/export`: загрузить как Non-Color (сырые значения), уменьшить 2048 → 1024 средним по блокам 2 × 2. У нормалей после усреднения: распаковать (× 2 − 1), нормировать, инвертировать зелёный (Unreal ждёт DirectX), запаковать обратно. Записать как данные PNG RGB в папку набора (родитель `source/`): `T_<Набор>_BaseColor.png`, `T_<Набор>_ORM.png`, `T_<Набор>_Normal.png`.
2. Объекты коллекции по алфавиту, каждый в свой FBX:
   - выделить только его, сделать активным;
   - запомнить `matrix_world`, поставить единичную — начало FBX совпадает с началом объекта. У корней поворот и так 0, а у подвижных деталей с поворотом покоя (рычаг, крышка) он тоже снимается: его задаёт блюпринт (`unreal.md`, «Подвижные детали»);
   - на время выгрузки все слоты получают временный материал `MI_<Набор>` без картинок;
   - добавить модификатор Triangulate с `keep_custom_normals` (касательным Unreal нужны те же треугольники, что в Blender);
   - выгрузить FBX с настройками из `unreal.md` (группы сглаживания, FBX Units Scale, только меш);
   - убрать модификатор, вернуть материал и `matrix_world`.
   - Имя файла — `SM_` и имя объекта: `FireExtinguisherBracket` → `SM_FireExtinguisherBracket.fbx`.

Что получается в FBX: один меш с именем объекта, без поворота, масштаб 1, начало в точке привязки; одна развёртка; один слот материала `MI_<Набор>`; картинок внутри нет. В Unreal текстуры импортируются отдельно, а `MI_<Набор>` — экземпляр `M_Kit` с тремя текстурами набора (`unreal.md`, «Импорт в Unreal»).

## ArmorPaint фоном

ArmorPaint собран из исходников: `~/Projects/armorpaint`, сборка `build_macos_clt.sh`, бинарь `~/Projects/armorpaint/paint/build/clt/ArmorPaint.app/Contents/MacOS/ArmorPaint`. `--help` — список ключей, `--api` — справка по API скриптов.

### Запуски

- Новый проект из меша: `ArmorPaint <набор>.fbx --background --script <набор>.build.c`. Сначала импортируется меш (появляются материал и слой `Layer 1` по умолчанию), потом выполняется скрипт.
- Выгрузка: `ArmorPaint <набор>.arm --background --export-textures png godot <папка>`.
- Каждый запуск ждать не дольше 150 с, потом убить процесс. Вывод (stdout и stderr) писать в лог и смотреть хвост: там число слоёв и ошибки.
- Ошибки шейдеров: открыть сохранённый проект фоном со скриптом, который заново заполняет слой (`ArmorPaint <проект>.arm --background --script <скрипт>`), — ошибки Metal идут в stdout. Строки «Could not resolve type» или «Shader compilation failed» значат, что слой сломан, хотя выгрузка проходит.

### Скрипт сборки

Скрипт — текст на C-подобном языке ArmorPaint (minic): функция `main` без аргументов, переменные типов `slot_material_t *`, `ui_node_t *`, `slot_layer_t *`; `printf` пишет в stdout. Его генерирует свой код из таблиц слоёв выше: тексты шейдеров — строки. Порядок вызовов:

| Что | Вызов API ArmorPaint |
|---|---|
| Импорт масок | `script_import_asset(путь, 0)` — по одному на файл, в порядке id, masks, noise, relief; индекс ассета = порядок |
| Новый материал и сделать текущим | `script_material_create(имя)`, `script_material_set(m)` |
| Флаги материала | поля `m->paint_base`, `paint_opac`, `paint_occ`, `paint_rough`, `paint_met`, `paint_nor`, `paint_height`, `paint_emis`, `paint_subs` |
| Узел выхода | `script_material_get_node("OUTPUT_MATERIAL_PBR")` |
| Узел шейдера | `script_material_create_node_at("SHADER_GPU", x, y)` |
| Вход шейдера | `script_material_add_input(sh, "RGBA", "Id")` и т. п. |
| Картинка | `script_material_create_node_at("TEX_IMAGE", x, y)`; кнопка 0 — File (индекс ассета), кнопка 1 — Color Space (0 Auto, 1 Linear, 2 sRGB, 3 DirectX Normal Map): `script_material_set_button(t, 0, индекс)`, `script_material_set_button(t, 1, 1.0)` |
| Связь | `script_material_connect(от, выход, к, вход)` |
| Выходы шейдера | `script_material_add_output(sh, "VALUE", "Opacity")` — также Occlusion, Roughness, Metallic |
| Текст шейдера | `script_material_set_text(sh, 0, текст)` |
| Применить | `script_material_update()` |
| Слой-заливка с текущим материалом | `script_layer_new_fill()`, `script_layer_set_name(l, имя)` |
| Флаги слоя | те же поля, что у материала, плюс `paint_nor_blend`, `paint_height_blend`; потом `script_layer_update(l)` |
| Число слоёв | `script_layer_count()` в `printf` |
| Сохранить | `project_filepath_set(путь .arm)`, затем `project_save(0)` |

Входы OUTPUT_MATERIAL_PBR: 0 Base Color, 1 Opacity, 2 Occlusion, 3 Roughness, 4 Metallic, 5 Normal Map. Выходы SHADER_GPU: 0 — Color (есть сразу), 1–4 — добавленные Opacity, Occlusion, Roughness, Metallic. Связи 0→0, 1→1, 2→2, 3→3, 4→4.

### Текст SHADER_GPU

- Язык — Kong: `float`, `float3`, `step`, `smoothstep`, `clamp`, `lerp`, `pow`, `max`.
- Вход читается как переменная с именем сокета в нижнем регистре (прочие знаки → `_`): сокет `Id` → `id`, RGBA и VECTOR — `float3`, VALUE — `float`.
- Выход пишется как `output.<имя>`: `output.color` (float3), `output.opacity`, `output.occlusion`, `output.roughness`, `output.metallic`.
- `mix` нет — писать a + (b − a) · t или `lerp`.
- Не звать `tex_noise_f` и `tex_noise_fbm`: функции попадают в шейдер в порядке хеш-таблицы, вызов оказывается раньше объявления, слой тихо остаётся пустым. Шум — только из картинки или своим кодом в тексте.
- Цвет из `output.color` попадает в выгруженный base как есть (значения файла). Раскодируются из sRGB только картинки на входе.

## Проверки

- Построение: число граней и треугольников, размеры — по рецепту.
- Развёртка: наложение 0; рамка UV внутри 0…1; зазор около 8 px на 2048; плотность одна у всех объектов (медиана px/м одинакова, отклонения — только на наклонных кольцах).
- Маски: незаполненных текселей 0; размер текселя; среднее износа и полости.
- ArmorPaint: в логе сборки 7 слоёв; в `source/export` четыре PNG 2048; emission пустой.
- Слои проверять по значениям пикселей выгрузки внутри островов, по материалам из карты id (поля искажают средние), а не по снимку окна. Например, у бирюзовой линзы base должен быть ровно (0,373; 0,776; 0,788), у резины шероховатость около 0,85.
- FBX: один меш с именем объекта; начало там, где точка привязки; слот материала `MI_<Набор>`, картинок внутри нет; текстуры `T_<Набор>_*` рядом 1024 × 1024, нормали с инвертированным зелёным.
- Осмотр в Blender (EEVEE с материалом набора) и в Unreal после импорта (`unreal.md`, «Первый импорт»).

## Подводные камни

- **Круглые пятна износа и грязи.** Расстояние до рёбер в шаге 5 считается в 3D до любого ребра объекта. Там, где ребро уходит в поверхность (угол прорези, рычаг, утопленный в плиту, головка винта), на поверхности вокруг получается круглое пятно, а не полоса вдоль ребра. Автор просил вместо таких «кружков» полосы вдоль геометрии. Исправление из поздних наборов: ребро учитывается для текселя, только если лежит в его плоскости (|направление ребра · нормаль грани текселя| < 0,5; из 8 ближайших точек берётся первая подходящая), а износ — только от рёбер своей связной части меша (винт, рычаг, плита). В `safety-equipment` и `ventilation` исправления ещё не было; при переделке лучше применить его и сказать автору.
- **Грязь.** Светлая матовая пыль на тёмном и на блестящем металле читается как белёсый налёт. В поздних наборах автор хотел грязь темнее, около (0,17; 0,155; 0,135), а на тёмных деталях — тёмную грязь. В этих наборах грязь ещё светлая (таблица Grime).
- **Сколы на узких фасках.** Скол до металла на фаске шириной 1–2 текселя рассыпается в тёмную крошку, похожую на грязь. На узких фасках — мягкая полоса, ширину которой меняет шум.
- **Шум по силе узкой полосы** (уже ячейки шума) рисует поперечные штрихи. Шумом менять ширину полосы, а не силу.
- **Острые грани.** Грани больше 35° становятся острыми: плоская тень и износ по ребру. Шаг скругления держать 30°.
- **Полосы на стыках частей.** Где две части сетки сходятся заподлицо, растеризация брала край за полость и рисовала тёмную вертикальную полосу. Таких стыков два вида. Первый — ребро с тремя гранями, две из них соосны: у пульта навигатора это средняя часть стола и его торец, третья грань — внутренняя стенка торца. Второй — два открытых края вплотную на одной плоскости: передний блок торца и его скошенная часть. `navigator_bake1.py` такие рёбра в полость не берёт (`flush_joint`). Внутренний угол поперёк — тумба под свесом стола — остаётся полостью. Швы панелей в карте высот автор тоже не хочет: у пульта оставлен только горизонтальный шов на лицевой полосе стола.
- **Нулевые треугольники.** Триангуляция многоугольника с отверстиями оставляет треугольники нулевой площади там, где углы отверстий на одной прямой; растеризация считает их рёбра вогнутыми и кладёт полосы грязи. В этих трёх наборах отверстий в гранях нет, но при новых деталях проверять число граней нулевой площади (должно быть 0).
- **Pack Islands в живом Blender** без override контекста 3D-вида падает с ошибкой контекста.
- **ArmorPaint, слои из окна.** Заливки, сделанные шагами агента в окне ArmorPaint, однажды вышли мусором (чёрный вид, шум в выгрузке). Те же слои, собранные фоновым скриптом, работали. Собирать только фоном.
- **Поля.** Заливки пишут только внутри островов, в полях остаётся серый 0,498 от `Layer 1`; собственного расширения у заливок нет. Поля заливаются в доводке.
- **Дрейф.** Даже непрокрашенные места выгрузки отличаются от исходника примерно на 4/255 — сверять с допуском.
- **Эмиссия** выгружается пустой: ArmorPaint хранит её только флагом для постоянного значения. Если нужна — писать картинку эмиссии после выгрузки самим (в этих наборах эмиссии нет).
- **Высота заливки** не попадает в выгруженную карту нормалей. Рельеф — только запечённой в Blender картой нормалей через слой Relief. У слоя Relief должна быть включена непрозрачность (у материала и слоя), иначе `_nor` выйдет плоским. У остальных слоёв нормаль выключена, иначе они его затрут.
- **Значения масок.** Без обратного кодирования в шейдере пороги на масках молча не срабатывают: 0,5 читается примерно как 0,21.
- **Предпросмотр масок.** Расширенные поля похожи на полосы — при осмотре затемнять поля.
- **Порядок зон.** Индекс зоны пишется в атрибут, список нельзя переставлять.

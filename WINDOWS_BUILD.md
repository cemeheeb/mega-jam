# Сборка под Windows: задание для сессии Claude Code

Этот файл — задание для сессии Claude Code на компьютере с Windows. Его написала сессия на Mac, где игра делалась.
Автору достаточно сказать: «Прочитай WINDOWS_BUILD.md и выполни».

## Цель

Получить упакованную сборку игры под Windows, убедиться, что она запускается и проходится, и собрать архив
для сдачи на Epic AI MegaJam 2026.

Дедлайн жёсткий: **понедельник 16 ноября 2026, 06:59 UTC+5** (15 ноября 17:59 PST). Опоздание — дисквалификация.
Времени мало, поэтому чинится только то, что мешает собрать и запустить игру под Windows.

## С кем ты работаешь

- Автор делает игру один и в Unreal впервые. Он сидит за этим компьютером.
- Разговор — по-русски. Тексты в игре английские, их не менять.
- Любое действие, которое автор делает руками, описывай явно: какое окно, какая кнопка, что должно получиться.
- После каждого шага говори, что именно проверено, а что нет.
- Если что-то не чинится за полчаса, скажи об этом и предложи, что срезать. Молча не продолжай.

В `CLAUDE.md` репозитория есть шаги про MCP и открытый редактор: они относятся к Mac. Здесь редактор открывать
не обязательно, всё делается из командной строки. `DESIGN.md` читать целиком не нужно: всё нужное — ниже.

## Проект

- Unreal Engine 5.8, проект на C++: `MegaJam.uproject`, один модуль `MegaJam` (Runtime).
- `Source/MegaJam/Run` — забег, `Menu` — меню и концовка, `Video` — настройки видео.
- Зависимости модуля: Core, CoreUObject, Engine, InputCore, Json, SlateCore, RenderCore.
- Стартовый уровень `Lvl_Menu`, игра идёт на `Lvl_Game`. Игру ведёт код (`ARunDirector`), комнаты — блюпринты
  `BP_Room_*`.
- Ассеты (`Content/`) лежат в Git LFS.

## Что проверено на Mac (коммит `a488a8c`, 16 ноября)

- Код собирается компилятором clang.
- Упаковка под Mac (Development) проходит.
- Упакованная игра проходит забег до победы самопроверкой. Эталон в журнале:
  - `Run: WON doors=6 notes=0 damage=0 health=100 medkits=0 seconds=39`
  - `Run: test done rooms=7 sets=5 health=100 damage=0 medkits=0`
- В сборке не нашлось только `/Game/Items/SnowGlobe/SM_SnowGlobe`: модели нет, в игре вместо неё кубик. Это норма.

## Что не проверено — это твоя работа

- **Компиляция MSVC.** Код ни разу не собирался этим компилятором. Это главный риск.
- Запуск под Windows: шейдеры Direct3D 12, шрифты, звук.
- Размер архива (предел джема — 1 ГБ).

Свежее всего и меньше всего проверено: `Menu/MenuDirector.cpp` и `Menu/MenuHUD.cpp` (сцена концовки и титры),
`Run/RunDirector.cpp`.

Чего ждать от MSVC: предупреждения, которые у него считаются ошибками (затенение имён C4456–C4459, приведения
типов), и пропущенные `#include`, которые на Mac закрывала другая раскладка unity-сборки («undeclared
identifier»). Исходники — в UTF-8 с русскими комментариями; UBT сам передаёт MSVC `/utf-8`. Кодировку файлов
не менять.

## Порядок

Команды — для `cmd`. `UE` — папка движка, обычно `C:\Program Files\Epic Games\UE_5.8`.

1. **Окружение.** Проверь, что стоят: Unreal Engine 5.8; Visual Studio 2022 с набором «Разработка игр на C++»
   и Windows SDK; Git с Git LFS. Чего нет — скажи автору, что и где поставить.
2. **Ассеты.** Убедись, что в `Content` настоящие файлы, а не указатели LFS (файл `.uasset` в 130 байт — указатель).
   Если указатели: `git lfs pull --include="Content/**"`. Папку `SourceArt` тянуть не нужно: это 800 МБ исходников.
3. **Код.** Сначала собери только код, это быстрее всей упаковки:
   ```
   "%UE%\Engine\Build\BatchFiles\Build.bat" MegaJamEditor Win64 Development -project="%CD%\MegaJam.uproject" -waitmutex
   "%UE%\Engine\Build\BatchFiles\Build.bat" MegaJam Win64 Shipping -project="%CD%\MegaJam.uproject" -waitmutex
   ```
   Ошибки чини по одной, наименьшей правкой.
4. **Пробная упаковка, Development.** В ней есть журнал, по нему проверяется игра:
   ```
   "%UE%\Engine\Build\BatchFiles\RunUAT.bat" BuildCookRun -project="%CD%\MegaJam.uproject" -platform=Win64 -clientconfig=Development -build -cook -stage -pak -archive -archivedirectory="%CD%\OutDev" -nop4 -utf8output -unattended
   ```
   Первый раз это 20–40 минут: код и шейдеры.
5. **Самопроверка.** Запусти упакованную игру:
   ```
   OutDev\Windows\MegaJam.exe /Game/Game/Maps/Lvl_Game -RunSelfTest -RunWin -RunSeed=42 -windowed -ResX=1280 -ResY=720 -log
   ```
   Игра сама проходит забег до победы, это около минуты. Жди в журнале `OutDev\Windows\MegaJam\Saved\Logs\MegaJam.log`
   строк `Run: WON` и `Run: test done`, потом закрой процесс: сам он может не выйти. Сверь с эталоном выше. Найди
   в журнале `SkipPackage` и `LogLoad: Error`: это ассеты, которых нет в сборке.
6. **Сборка для сдачи, Shipping.** Запусти `package_windows.bat` из корня проекта. Результат — `Out\Windows`,
   журнал — `package_windows.log`. В Shipping журнала игры нет и отладка выключена.
7. **Проверка глазами.** Попроси автора запустить `Out\Windows\MegaJam.exe` и пройтись по списку:
   - меню с кораблём у чёрной дыры, музыка;
   - NEW GAME: каюта, дверь с кодом (пустой код и Enter — новый корабль), за ней рубка;
   - шрифты свои, у вещей модели, в комнатах мебель, есть звук и голос героя;
   - концовка: `Out\Windows\MegaJam.exe /Game/Game/Maps/Lvl_Menu -MenuEnding` — сцена на 29 секунд с титрами.
8. **Архив.** Папку `Out\Windows` запакуй в `ИмяКоманды_ИмяИгры.zip`. Имя команды и название игры спроси
   у автора: название ещё не выбрано. Проверь, что архив меньше 1 ГБ. Распакуй его в другую папку и запусти оттуда.
9. **Отчёт.** Что собрано, что проверено и чем, что не проверено, размер архива, список правок.

## Правки кода

- Только ради сборки и запуска под Windows. Поведение игры не меняется.
- Каждая правка — отдельный коммит с понятным сообщением. Отправлять (`git push`) — когда автор скажет: правки
  должны вернуться на Mac.
- Если проект распакован из архива, а не склонирован, веди список правок с диффами в `WINDOWS_CHANGES.md`.

## Чего не делать

- **Не трогать ассеты** (`*.uasset`, `*.umap`). Пересобрать их здесь нельзя: скрипты `tools/ue` и `tools/blender`
  рассчитаны на Mac с открытым редактором. Эти скрипты не запускать.
- Не менять механику, тексты и баланс.
- Не сокращать списки упаковки в `Config/DefaultGame.ini` (`MapsToCook`, `DirectoriesToAlwaysCook`,
  `DirectoriesToAlwaysStageAsUFS`): код грузит ассеты по путям, шрифты читает из `Content/Fonts`.
- Не включать отладку. Отладочные клавиши K и H есть только в редакторе (`#if WITH_EDITOR`), так и должно
  остаться. Ключи `-Run…` и `-Menu…` — для проверок из командной строки, игрок их не задаёт.
- Не обновлять движок и не менять `EngineAssociation`.
- Не отправлять никуда личные данные автора.

## Известные мелочи

- В `MegaJam.uproject` включены плагины только для редактора: ModelContextProtocol, EditorToolset, UMGToolSet,
  ConfigSettingsToolset, AutomationTestToolset, ModelingToolsEditorMode. Код игры их не использует. Если сборка
  ругается, что какого-то из них нет, отключи его в `.uproject` (`"Enabled": false`) и скажи автору.
- `ProjectName` в `Config/DefaultGame.ini` остался от шаблона: «Third Person BP Game Template». Если автор назовёт
  игру, поменяй его на название. Это единственная уместная правка конфигов.
- Путь к проекту — короткий и без русских букв, например `C:\MegaJam`: у внешних акторов длинные имена файлов.
  При клонировании пригодится `git config --global core.longpaths true`.
